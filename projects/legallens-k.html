/* overview */

왜 HWP 계약서인가

한국 법무 현장의 계약서는 여전히 HWP 포맷이 압도적이지만, 글로벌 AI 계약 분석 도구는 이 포맷을 다루지 못합니다. 이 간극이 곧 제품 기회라고 판단했습니다. 타깃 사용자는 사내 변호사와 로펌 실무자 — 검토할 계약은 많고 시간은 없는 사람들입니다.

단순 요약 챗봇이 아니라, 분석 → 위험 판정 → 점수화를 다단계로 수행하는 에이전트 파이프라인으로 설계했습니다.

/* architecture */

아키텍처

모노레포 구조에서 백엔드와 프론트엔드를 분리하고, LangGraph가 전체 분석 흐름을 오케스트레이션합니다.

// analysis pipeline HWP Upload → hwp-parser → 조항 분리 → rule-based detector // 독소조항 1차 탐지 → RAG retrieval // 공정위 표준계약서 대조 (Qdrant) → LLM risk scoring // 다단계 위험도 판정 → report // 조항별 리스크 리포트

FastAPI(백엔드) + React/TypeScript(프론트엔드) + PostgreSQL(데이터) + Qdrant(벡터 검색) + Redis(큐/캐시) 구성이며, LLM은 Claude Sonnet을 LangGraph로 오케스트레이션합니다.

/* security */

  • 법무 사용자 특성상 데이터 처리 방식에 대한 신뢰가 도입의 전제 조건
