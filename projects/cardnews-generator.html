이미지 생성 AI의 약점을 구조로 우회하다

이미지 생성 AI로 카드뉴스를 만들면 텍스트가 깨지거나 너무 작게 렌더링되는 문제가 반복됩니다. 원인을 추적해보니 모델의 한계가 아니라 제약 없는 입력이 문제였습니다. 그래서 접근을 바꿨습니다 — 텍스트는 AI에게 맡기지 않고 HTML/CSS가 렌더링하고, AI는 카피만 생성합니다.

/* architecture */

2계층 아키텍처

// content layer — 무엇을 말할지 주제 입력 → Gemini API → 8장 카피 JSON schema: { headline: ≤10자, sub: ≤20자 } // 디자인 파손 원천 차단 // rendering layer — 어떻게 보일지 HTML/CSS 템플릿 → html2canvas (×10/3 scale) → 324px 프리뷰 → 1080px PNG → JSZip 일괄 다운로드

핵심 결정은 글자수 제약을 프롬프트가 아닌 스키마로 강제한 것입니다. headline 10자, sub 20자 제한을 JSON 스키마 레벨에서 검증해, 어떤 주제를 넣어도 디자인이 깨지지 않습니다. 렌더링 계층이 분리되어 있어 추후 이미지 AI나 Canva API로 교체해도 파이프라인 재설계가 필요 없습니다.

/* key-work */

구현 디테일

01단일 파일 SPA

빌드 도구 없이 브라우저에서 바로 열리는 index.html 하나로 완결 — 비개발자도 즉시 사용 가능합니다.

02고해상도 캡처 파이프라인

324px 프리뷰 카드를 html2canvas 10/3 스케일로 캡처해 인스타그램 규격 1080px PNG로 출력합니다.

  • 개별 카드 PNG 다운로드와 8장 ZIP 일괄 다운로드(JSZip + FileSaver) 모두 지원

03프롬프트 디버깅

초기 버전에서 텍스트가 작게 나오는 원인을 스타일 가이드의 '작고 짧게' 지시문으로 특정하고, headline-size·80–90% 폭 지시로 교체해 해결했습니다.

  • 증상이 아니라 프롬프트의 근본 원인을 추적하는 디버깅 경험
