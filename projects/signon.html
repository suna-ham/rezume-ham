전자계약 시장의 후발주자가 신뢰를 얻는 방법

SignOn(signon.co.kr)은 모두싸인·글로싸인 등 선발 주자가 있는 한국 전자계약 시장의 B2B SaaS입니다. 후발주자가 기업 고객의 신뢰를 얻으려면 법적 효력에 대한 확신과 일관된 브랜드 경험이 필요했고, 저는 디자이너 겸 퍼블리셔 겸 마케터로서 이 신뢰의 화면을 처음부터 만들었습니다.

Primary Red #A61118과 Warm Beige #F7E6CA를 축으로 한 브랜드 컬러 시스템을 CSS 커스텀 프로퍼티로 토큰화해, 모든 페이지가 같은 언어로 말하게 했습니다.

/* challenge */

제약 조건: 운영 중인 JSP 레거시

// PROBLEM

  • 운영 중인 JSP 레거시 — 공용 스타일시트는 수정 불가, 추가만 허용되는 제약
  • 페이지마다 흩어진 인라인 스타일과 중복 CSS로 유지보수 비용 증가
  • 전담 기획자·마케터 부재 — 경쟁사 분석부터 카피라이팅까지 직접 수행 필요
  • 이모지 아이콘의 OS/브라우저별 렌더링 불일치 등 디테일 품질 문제

// APPROACH

  • CSS 추가 전용 제약 안에서 스코핑 전략(부모 셀렉터 한정)으로 충돌 없이 확장
  • 인라인 스타일을 pages.css로 통합, :root 변수 병합으로 중복 제거
  • 경쟁사 3사(모두싸인·글로싸인·eformsign) 구조 분석 → 기획서 작성 → 구현의 원스톱 수행
  • 이모지를 currentColor 상속 인라인 SVG로 교체해 브랜드 토큰과 연동

/* key-work */

주요 작업

01법적효력/보안 가이드 페이지 — 기획부터 구현까지

경쟁사 3사의 신뢰 페이지를 분석해 6섹션 구조의 기획서를 작성하고, 풀 HTML로 직접 구현했습니다.

  • 전자서명법·전자문서법·민법 3개 법률 아코디언 UI, 증적 프로세스 플로우, 보안 기능 그리드
  • 스크롤 기반 사이드 내비게이션 액티브 추적, 스크롤 리빌 애니메이션, 모바일에서 가로 탭으로 변형되는 반응형

02CSS 아키텍처 리팩토링

legal.html의 인라인 스타일 전체를 pages.css로 병합하면서 기존 코드를 한 줄도 삭제하지 않는 제약을 지켰습니다.

  • 중복 :root 변수는 병합, 페이지 전용 변수만 추가
  • .content-area .feature-card 식 스코핑으로 클래스명 충돌 차단

03React 인터랙티브 제품 데모

Arcade Software의 핫스팟 워크스루 메커니즘을 분석해, 외부 툴 없이 React 단일 컴포넌트로 재구현했습니다.

  • 서명 요청 보내기 8단계 플로우 — 핫스팟 펄스, 오토플레이(3.2s), 키보드 내비게이션, 진행 바
  • 스크린샷 대신 각 단계를 React 컴포넌트로 렌더링 → 수정·다국어 대응이 재캡처 없이 가능

04대시보드 정보구조 재설계

계약 현황 7개 카드를 진행/처리/요주의 3그룹으로 재구조화하고, 회원관리 위젯은 레퍼런스 기반 다크 테마로 리디자인했습니다.

  • 요주의 지표(만료/거절/취소)는 경고 컬러와 큰 숫자로 운영자 시선 유도

05콘텐츠 마케팅 시스템

인지→신뢰→적용→전환 4단계 퍼널로 블로그 20제를 설계하고, FAQ 27개 항목을 6개 카테고리로 전면 개편했습니다.

  • AEO 카드뉴스 8장 시리즈 — Figma 컴포넌트 아키텍처 + Google Sheets→Figma MCP 데이터 주입 설계
  • Higgsfield AI 생성과 SVG 코드 애니메이션을 결합한 인스타그램 캐러셀 하이브리드 제작 전략
