/* overview */

디자인이 코드가 되는 길을 자동화하면

퍼블리셔의 반복 업무 상당수는 '디자인 시안을 마크업으로 옮기고, 결과를 눈으로 비교 검수'하는 일입니다. 이 사이클 전체를 에이전트 파이프라인으로 자동화할 수 있는지 — 디자인 생성, 코드 변환, 시각적 QA를 각각 다른 AI에게 맡기고 사람은 승인만 하는 구조를 설계했습니다.

/* architecture */

파이프라인 설계

Google Stitch → Claude → Gemini Vision (디자인 생성) (코드 변환) (시각 QA) │ │ │ └── Zod schema ──┴── contract-first 핸드오프 │ Human-in-the-loop 승인 게이트

핵심 설계 결정 세 가지입니다. 첫째, 에이전트 간 핸드오프를 마크다운 파일 전달이 아닌 Zod 스키마 검증 기반 contract-first로 설계해 형식 오류를 경계에서 차단합니다. 둘째, 파일 워처 대신 메시지 큐·오케스트레이션 레이어(에이전트 간 Temporal, 에이전트 내 LangGraph)를 두어 재시도와 상태 추적을 보장합니다. 셋째, 비용이 큰 Vision API 호출을 3단계 Visual QA(저비용 휴리스틱 → 선별 → 정밀 비교)로 계층화해 호출량을 통제합니다.

/* key-work */

현실적인 도입 전략

01Human-in-the-loop 게이트

완전 자동화 대신 핵심 단계마다 사람의 승인 게이트를 설계 — 자동화의 속도와 품질 책임을 동시에 확보합니다.

02레거시 호환 레이어

산출 코드가 JSP 레거시·한국어 UX 관례와 충돌하지 않도록 호환 계층을 별도 정의했습니다.

03단계적 검증 로드맵

전면 도입이 아닌 1주 수직 슬라이스 POC → 3–4주 단일 섹션 실전 검증 → 가치 확인 후 확장의 3단계로 리스크를 통제했습니다.

  • '60일 풀 구축'보다 '1주 POC'를 먼저 — 기술 선택보다 도입 순서가 성패를 가른다는 판단
